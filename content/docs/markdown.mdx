Bodies render GitHub-flavored markdown (bold, italic, strikethrough, code, links, images, lists, quotes, tables, newlines) via a shared renderer in `@lst97-oss/last-comments-widgets/client`. Raw HTML is stripped, links allow `http(s):`/`mailto:` only.

## Composer

Every composer is a muted panel with:

- An icon toolbar (Bold/Italic/Quote/Inline code/Code block/Link/Bullet/Numbered).
- A Write/Preview toggle.
- A right-aligned live character count against `bodyLimit` (default `10,000`, counted before trimming; red once over, with the submit button disabled and the composer refusing to post).
- A `Styling with Markdown is supported` hint.

Set `bodyLimit` to whatever the host server enforces; the plain-HTML port reads it from `data-lc-body-limit`.

## Syntax highlighting

In the React widget, fenced code blocks with a language are upgraded after first paint with [Shiki](https://shiki.style/) (`vitesse-light`/`vitesse-dark`), wrapped in the same docs-style frame as the last-comments blog (language label + copy button). The upgrade is lazy — no Shiki is downloaded until a fence exists — and an unknown or missing language keeps the plain `<pre>` fallback.

The Code block action inserts a fenced block with the `language` placeholder selected; inline code keeps its own button. The Vue, Angular and vanilla composers still use the inline-code action and render plain fences until they are ported.

```bash
bun add shiki
```

Shiki is an optional peer — install it only if comment code fences should be syntax-highlighted.

## Sanitising

`safeUrl` and `renderMarkdown` are exported from `@lst97-oss/last-comments-widgets/client` for hosts rendering bodies themselves: raw HTML is stripped and links are restricted to `http(s):`/`mailto:`.
